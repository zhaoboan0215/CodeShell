# TUI 运行时模型切换 Spec

## 背景

CodeShell 当前只能在 TUI 启动时从多个 Provider 中选择一次；进入会话后，模型固定，切换需要退出并修改配置或重新启动。

## 目标

- 在 TUI 会话中增加模型切换能力，无需重启即可在 `deepseek-flash` 和 `deepseek-v4-pro` 之间切换。
- 切换只对当前运行生效，不写入配置。
- 保留现有对话上下文，下一条消息由新模型处理。

## 功能需求

- F1：TUI 注册 `/model` 命令，且能通过 `/help` 查看用法。
- F2：输入 `/model` 时显示选择列表，包含 `deepseek-flash` 和 `deepseek-v4-pro`，并标记当前模型。
- F3：支持 `/model deepseek-flash` 和 `/model deepseek-v4-pro` 直接切换。
- F4：切换成功后，下一条用户消息必须由新模型处理，并同步更新界面上的模型名称。
- F5：保留当前会话、完整对话上下文、权限模式、工具、MCP、记忆及任务状态。
- F6：切换只在当前运行期间生效，不写入任何配置文件。
- F7：重复选择当前模型时给出明确提示，不重复初始化。
- F8：输入不支持的模型时保持原模型不变，并显示两个可用模型。
- F9：模型正在生成回复时不执行切换，提示用户等待当前响应结束。

## 非功能需求

- N1：切换操作必须是原子的；新模型初始化失败时回退到原模型，不能留下半切换状态。
- N2：切换过程不得发送对话请求，也不得在界面或日志中暴露 API Key。
- N3：不得重复连接 MCP、重复注册工具或重复创建团队、任务和记忆组件。
- N4：除模型客户端及模型相关参数外，不重建当前会话运行状态。
- N5：`--model` 启动参数、Remote 模式和非交互模式本轮保持原行为。
- N6：自动测试不得依赖真实 DeepSeek 网络或有效 API Key。
- N7：现有功能回归结果不得退化，保留当前已知 Hook 失败基线。

## 不做的事

- 不从 DeepSeek API 动态拉取模型列表。
- 不允许输入两个指定模型之外的任意模型 ID。
- 不保存“上次选择的模型”，重启后仍按现有启动流程选择。
- 不增加 `--model` 启动参数。
- 不为 Remote 或非交互模式增加运行中切换能力。
- 不实现 DeepSeek 与 OpenAI、Anthropic 等跨 Provider 动态切换。
- 不因切换模型创建新会话、清空上下文或中断当前生成中的回复。

## 验收标准

- AC1：`/help` 中出现 `/model`，`/help model` 显示列表和直接参数两种用法。
- AC2：输入 `/model` 能看到两个模型，并明确标出当前模型。
- AC3：分别切换到两个模型后，后续请求使用对应模型客户端，界面模型标签同步变化。
- AC4：切换前后的会话 ID、消息历史、工具、MCP、记忆、任务及权限状态保持不变。
- AC5：切换前后配置文件内容完全一致，重启后不保留临时选择。
- AC6：重复选择当前模型或输入无效模型时行为符合提示要求，且当前模型不变。
- AC7：回复生成期间尝试切换时被安全拒绝，当前请求和模型状态不受影响。
- AC8：模拟新模型初始化失败时仍继续使用原模型。
- AC9：新增测试全部通过；完整回归保持至少 `738 passed, 1 skipped`，且不增加新的失败。
- AC10：端到端验证 `/model` 列表选择和 `/model <模型>` 直接切换两条路径。
