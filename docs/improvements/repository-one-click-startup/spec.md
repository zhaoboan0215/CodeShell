# CodeShell 仓库一键启动与交付体验 Spec

## 背景

CodeShell 已具备终端交互、模型调用、MCP、记忆、权限控制和多 Agent 等能力，但当前仓库缺少完整的安装与使用说明、可安全复制的配置示例和环境诊断入口。新用户克隆仓库后，需要自行判断依赖安装、配置位置、密钥设置和启动命令；已注册的命令行入口在部分环境中也不能稳定导入项目包。

本轮改造聚焦代码仓库的本地交付体验，不发布到 PyPI。外部模型服务的 API Key 仍由使用者自行准备。

## 目标

- 让使用者克隆仓库后，通过一条正式启动命令自动安装锁定依赖并启动 CodeShell。
- 让首次配置、环境依赖和启动失败都能得到清晰、可执行的提示。
- 提供环境诊断能力，减少 Python、模型配置、Node.js 和 MCP 问题的排查成本。
- 补全适合作为公开作品展示的项目文档和自动化交付验证。
- 每项实际修改都留下明确记录，说明修改位置、原问题、修改内容和验证结果。

## 功能需求

- F1：仓库必须提供一条正式的一键启动命令；在已安装基础工具的前提下，该命令自动创建或复用隔离环境、按锁文件同步依赖并启动终端界面，不要求用户手动激活虚拟环境。
- F2：项目的命令行入口必须在支持的 Python 版本上稳定工作；模块启动与安装后的命令启动应表现一致，并支持查看帮助、交互启动和非交互启动。
- F3：仓库必须提供不含真实密钥的完整配置示例；首次缺少配置或密钥时，程序必须给出配置文件位置、所需字段和下一步操作，不直接输出难以理解的异常堆栈。
- F4：项目必须提供环境诊断命令，检查 Python 版本、依赖环境、配置结构、Provider、API Key 是否已设置、所配模型是否可访问，以及启用 MCP 时所需的 Node.js/npx；诊断结果必须逐项显示通过、警告或失败及修复建议。
- F5：项目必须提供完整的项目说明文档，至少包含项目定位、核心功能、架构概览、环境要求、快速开始、Provider 配置、MCP 配置、常用命令、测试方式、故障排查、安全提示和真实运行截图。
- F6：仓库必须通过自动化流程验证 Python 3.11、3.12 和 3.13 下的干净安装、命令行帮助、配置校验、环境诊断和启动冒烟场景。
- F7：本轮交付必须提供可审阅的变更清单；每项记录明确列出修改文件、修改前的问题、实际修改、用户可见影响和验证证据。
- F8：每次独立改进必须按修改主题建立单独的归档目录，并将该次改进的 `spec.md`、`plan.md`、`task.md`、`checklist.md` 和最终变更报告集中保存；后续改进不得与本次文档混放。

## 非功能需求

- N1：任何示例、日志、诊断输出和自动化流程均不得包含真实 API Key；密钥只显示“已配置/未配置”或脱敏结果。
- N2：重复执行一键启动和诊断命令必须安全、幂等，不破坏现有配置或虚拟环境。
- N3：没有网络、Provider 不可达或 MCP 依赖不可用时，诊断必须区分本地配置错误与外部服务错误。
- N4：保持现有配置文件兼容，不要求现有用户迁移配置才能继续启动。
- N5：新增行为必须有自动化测试，且不得通过静默跳过或删除测试来制造通过结果。
- N6：支持范围以 macOS 和 Linux 为主；涉及平台差异时必须给出明确提示。
- N7：改进归档目录使用稳定、可读的英文主题名，目录移动后文档内部引用仍必须有效。

## 不做的事

- 不发布 PyPI 包，不设计版本发布、签名或上传流程。
- 不新增 AI 对话、记忆、多 Agent、MCP 工具或远程模式等业务功能。
- 不更换当前 Provider，也不修改模型推理协议和计费行为。
- 不修复此前被明确跳过的危险命令 Hook 问题；相关现状只如实记录，不纳入本轮实现。
- 不承诺 Windows 原生终端的一键启动支持。
- 不自动申请、生成或写入第三方 API Key。

## 验收标准

- AC1：在一个干净的仓库副本中，准备好基础工具和 API Key 后，只运行文档指定的一条启动命令，即可完成依赖同步并看到 CodeShell 输入界面。
- AC2：在 Python 3.11、3.12 和 3.13 环境中，正式命令行入口均能正常显示帮助，不出现项目包导入错误。
- AC3：删除或暂时移走项目配置后启动，用户能看到包含配置位置、必填字段和操作步骤的错误提示，且不显示内部异常堆栈。
- AC4：运行环境诊断命令时，每个检查项都有明确状态；正常配置返回成功，关键项失败返回非零状态，并且输出中不出现完整密钥。
- AC5：仓库中的配置示例可通过项目自身的配置校验，且扫描不到真实密钥。
- AC6：新用户只阅读项目说明文档即可完成配置、启动、运行测试和处理常见启动错误。
- AC7：自动化流程在 Python 3.11、3.12 和 3.13 上完成安装与交付路径冒烟验证，并明确报告结果。
- AC8：交付报告逐项列出本轮所有修改文件、修改原因、具体内容及实际验证结果。
- AC9：本轮变更不包含危险命令 Hook 的实现修改；现有相关测试状态在最终报告中如实披露。
- AC10：本轮五份 Markdown 文档全部位于 `docs/improvements/repository-one-click-startup/`，仓库根目录不残留本轮流程文档副本。
